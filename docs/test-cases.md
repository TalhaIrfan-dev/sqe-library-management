# Library Management System Test Cases

This document contains the functional test cases for the Library Management System. Each test case is traceable to a functional requirement and includes preconditions, execution steps, expected results, priority, test type, and execution results.

| ID | Title | Requirement | Preconditions | Steps | Expected | Priority | Type | Result | Note |
|---|---|---|---|---|---|---|---|---|---|
| TC-01 | Add a book with a valid new ISBN | FR-01 | The library system is running and the ISBN does not already exist in the catalog. | 1. Enter a valid book title. \<br> 2. Enter a valid author name. \<br> 3. Enter a valid ISBN. \<br> 4. Enter a positive number of copies. \<br> 5. Add the book to the library. | The book is added successfully to the catalog with the specified title, author, ISBN, and number of copies. | High | Positive / Functional | PASS | Book was added successfully with the specified information. |
| TC-02 | Reject a book with a duplicate ISBN | FR-03 | A book with ISBN `9780132350884` already exists in the catalog. | 1. Attempt to add another book with a different title and author. \<br> 2. Use the existing ISBN `9780132350884`. \<br> 3. Provide a positive number of copies. \<br> 4. Submit the book for addition. | The system rejects the new book and raises an `IllegalArgumentException` indicating that the ISBN already exists. The duplicate book is not added to the catalog. | High | Negative / Functional | PASS | Duplicate ISBN was rejected successfully. |
| TC-03 | Reject a book with an invalid ISBN | FR-02 | The library system is running. The provided ISBN is empty, malformed, or otherwise invalid according to the system's validation rules. | 1. Enter a valid book title. \<br> 2. Enter a valid author name. \<br> 3. Enter an invalid ISBN value. \<br> 4. Enter a positive number of copies. \<br> 5. Attempt to add the book. | The system rejects the book and does not add it to the catalog. An appropriate validation error is produced. | High | Negative / Functional | PASS | Invalid ISBN was rejected successfully after ISBN format validation was implemented. Fixed in Issue #23. |
| TC-04 | Borrow a book when copies are available | FR-06 | A registered member exists. A book exists in the catalog and has at least one available copy. The member has not already borrowed the book and has not reached the borrowing limit. | 1. Identify a registered member. \<br> 2. Identify a book with at least one available copy. \<br> 3. Borrow the book using the member ID and book ISBN. | The book is successfully added to the member's borrowed books. The available copy count decreases by one, while the total copy count remains unchanged. | High | Positive / Functional | PASS | Book was borrowed successfully and available copies decreased by one. |
| TC-05 | Reject borrowing when no copies are available | FR-06 | A registered member exists. The requested book exists in the catalog but has zero available copies. | 1. Identify a registered member who has not reached the borrowing limit. \<br> 2. Select a book with zero available copies. \<br> 3. Attempt to borrow the book using the member ID and ISBN. | The system rejects the borrowing request and raises an `IllegalArgumentException` indicating that no copies are available. The member's borrowed-book list and book copy count remain unchanged. | High | Negative / Functional | PASS | Borrowing was rejected when no copies were available. |
| TC-06 | Return a book currently borrowed by the member | FR-07 | A registered member has currently borrowed the selected book. The book has one fewer available copy because it is on loan. | 1. Identify the member who currently has the book. \<br> 2. Use the member ID and book ISBN to return the book. | The system successfully removes the book from the member's borrowed-book list and increases the book's available copy count by one, while the total copy count remains unchanged. | High | Positive / Functional | PASS | Book was returned successfully and available copies increased by one. |
| TC-07 | Reject return of a book not borrowed by the member | FR-07 | A registered member exists. The selected book is either not borrowed by the member or was borrowed by another member. | 1. Identify a member who does not currently have the selected book. \<br> 2. Provide the member ID and the book ISBN. \<br> 3. Attempt to return the book. | The system rejects the return request and raises an `IllegalArgumentException` indicating that the book was not borrowed by this member. The member's borrowed-book list and book copy count remain unchanged. | High | Negative / Functional | PASS | Return was rejected because the book was not borrowed by the member. |
| TC-08 | Allow a member to borrow books up to the allowed limit | FR-06 | A registered member exists. At least three different books have available copies. The member has no currently borrowed books. | 1. Borrow the first available book. \<br> 2. Borrow the second available book. \<br> 3. Borrow the third available book. | All three borrowing requests are accepted successfully. The member has exactly three borrowed books, which is the allowed borrowing limit. | High | Boundary / Functional | PASS | Member successfully borrowed three books, reaching the allowed limit. |
| TC-09 | Reject borrowing beyond the allowed limit | FR-06 | A registered member already has three borrowed books, which is the maximum allowed limit. Another book with an available copy exists. | 1. Identify the member who already has three borrowed books. \<br> 2. Select another available book that the member has not borrowed. \<br> 3. Attempt to borrow the fourth book. | The system rejects the fourth borrowing request and raises an `IllegalArgumentException` indicating that the borrowing limit has been reached. The member remains at three borrowed books. | High | Negative / Boundary / Functional | PASS | Fourth borrowing attempt was rejected at the borrowing limit. |
| TC-10 | Calculate fine when there are zero overdue days | FR-07 | A book has been returned with zero overdue days. The system's fine-calculation rules are available for execution. | 1. Record a book return with zero overdue days. \<br> 2. Execute the fine-calculation operation. \<br> 3. Observe the calculated fine amount. | The system calculates the fine for zero overdue days according to the defined fine policy. No overdue fine should be charged when the policy specifies no fine for zero overdue days. | Medium | Positive / Functional | PASS | Fine calculation returned Rs. 0 for zero overdue days. |
| TC-11 | Calculate fine for a mid-range overdue period | FR-07 | A book has been returned after a mid-range overdue period. The system's fine-calculation rules are available for execution. | 1. Select a return scenario with a mid-range number of overdue days. \<br> 2. Execute the fine-calculation operation. \<br> 3. Observe the calculated fine amount. | The system calculates the fine according to the applicable fine tier for the specified mid-range overdue period. The calculated amount matches the defined fine policy. | Medium | Positive / Functional | PASS | Fine calculation returned the expected amount for the mid-range overdue period. |
| TC-12 | Calculate fine at an overdue-tier boundary | FR-07 | The system defines fine tiers with a boundary between two overdue ranges. A book is returned exactly at that boundary. | 1. Identify the exact number of overdue days at the fine-tier boundary. \<br> 2. Execute the fine-calculation operation using that overdue period. \<br> 3. Observe the calculated fine amount. | The system applies the correct fine tier at the boundary and calculates the fine according to the defined fine policy. The boundary value is handled consistently without being assigned to the wrong tier. | High | Boundary / Functional | PASS | Fine calculation correctly handled the overdue-tier boundary. |
| TC-13 | Search for a book by title and ISBN | FR-04 | A book exists in the library catalog with a known title and ISBN. | 1. Search for the book using its title. \<br> 2. Verify the matching book information. \<br> 3. Search for the same book using its ISBN. \<br> 4. Verify the matching book information. | The system returns the correct book information when searched by title and when searched by ISBN. | High | Positive / Functional | PASS | The same book was correctly found using both title and ISBN. |
| TC-14 | Add a library member and reject a duplicate member ID | FR-05 | The library system is running and the member ID does not already exist. | 1. Enter a valid member ID and member name. \<br> 2. Add the member to the library. \<br> 3. Attempt to add another member using the same member ID. \<br> 4. Submit the second member for addition. | The first member is added successfully. The system rejects the second member and raises an `IllegalArgumentException` indicating that the member ID already exists. | High | Positive / Negative / Functional | PASS | Member was added successfully and the duplicate member ID was rejected. |
